# Чек-лист запуска (2026-09-16)

Собран из требований ТЗ («Готово, когда…») и того, что накопилось на стенде.
Цифры — фактические, снятые скриптами `tools/qa/*` на 2026-09-16; их можно
пересчитать в любой момент, а не переписывать вручную.

Документ отвечает на один вопрос: **что мешает открыть магазин и от кого это
зависит.** Здесь нет задач по вёрстке — они в остальных файлах `docs/`.

---

## 0. Решения пользователя от 2026-09-18

Приняты после закрытия этапа редактируемости (тег `editor-stage-done`).
Они меняют исходную рамку ТЗ, где production считался источником товаров.

1. **Товары, ID, URL и контент с production не переносятся.** Сайт работает
   на наборе товаров, подготовленном на стенде (61 товар). Этапы ТЗ «аудит
   production» и «backup и клон» для текущей работы не нужны.
2. **Production не трогаем, доступ и его бэкап не нужны.**
3. **ЮKassa (YooMoney), СДЭК и Telegram готовятся самостоятельно** до
   состояния «заказчику остаётся подставить свои данные». Реальные ключи,
   токены и аккаунты не выдумываются; где без данных заказчика не обойтись —
   оставляется понятное место подстановки и запись здесь. Это отдельный
   этап, после сквозной браузерной QA.
4. **Метрика и GTM.** ТЗ требует «сохранить Метрику/GTM и рекламные события»
   и в критериях «аналитика сохранена», **конкретных целей и событий в ТЗ
   нет**. Поэтому события не добавляются. Техническая часть уже готова (см.
   таблицу ниже): заказчик вписывает номера, и при боевом режиме счётчики
   начинают работать.
5. **Политика конфиденциальности** — текст даст заказчик; юридический текст
   не пишем. Техническая часть готова (см. ниже).
6. **Ссылки App Store, Google Play, Telegram и мессенджеров** — даст заказчик,
   URL не выдумываем. Места для них перечислены ниже.

### Что заказчик подставляет сам и где

| Значение | Куда | Что произойдёт |
|---|---|---|
| Номер счётчика Яндекс.Метрики (только цифры) | Настройки → Общие, поле «Яндекс.Метрика» | счётчик появится на всех страницах |
| ID контейнера GTM (`GTM-XXXXXX`) | Настройки → Общие, поле «Google Tag Manager» | контейнер и его запасной кадр для браузеров без JS появятся на всех страницах |
| Текст политики конфиденциальности | Страницы → «Политика конфиденциальности» (ID 3, адрес `/privacy-policy/`): заменить содержимое заготовки WordPress и нажать «Опубликовать» | заработает ссылка в подвале; страница уже выбрана политикой сайта в Настройки → Конфиденциальность |

Счётчики выводятся только при `WP_ENVIRONMENT_TYPE = production` (см.
раздел 2) — на стенде поля можно заполнить заранее, визиты в статистику
заказчика при этом не уйдут. Исключение — счётчик DMP Programmatic.ru: он
вставлен по просьбе заказчика и работает везде, включая стенд
(`wp-content/mu-plugins/whoopstore-site/analytics.php`).

### Ссылки, которые ждут адресов

Вписывает разработчик — это правка HTML внутри паттернов, заказчику её
делать не нужно (см. `docs/client-editing-guide.md`, раздел 5).

| Где на сайте | Паттерн (Внешний вид → Редактор → Паттерны) | Сейчас | Что нужно |
|---|---|---|---|
| «Приложения Whoop» → карточка App Store, кнопка «Скачать» | Приложения Whoop | `href="#"` в блоке «HTML-код» | адрес приложения в App Store |
| «Приложения Whoop» → карточка Play Market, кнопка «Скачать» | Приложения Whoop | `href="#"` в блоке «HTML-код» | адрес приложения в Google Play |
| «Приложения Whoop» → третья карточка, кнопка «Подключить» | Приложения Whoop | `href="#"` в блоке «HTML-код» | адрес, куда ведёт «Подключить» |
| «Подпишитесь на нас в Телеграм!» → кнопка «Подписаться» | Телеграм — подписка | `href="#"` у кнопки | адрес Telegram-канала; меняется и через редактор (ссылка кнопки) |
| «Контакты» → иконки MAX и Telegram | Контакты | иконки без ссылок, скрыты от скринридеров | адреса MAX и Telegram; каждую иконку обернуть в ссылку и дать ей подпись |

Тот же паттерн «Контакты» стоит на четырёх страницах, «Телеграм — подписка» —
тоже, поэтому каждая ссылка вписывается один раз.

Открытый вопрос, не входящий в эти пункты: у галочки «Я согласен(-а) с
политикой конфиденциальности» в форме заказа нет ссылки на саму политику.
Нужна ли она — решение по макету.

## 2. Переключение стенда в боевой режим

Это надо сделать **в момент запуска**, не раньше: пока стенд закрыт, часть
пунктов специально работает наоборот.

1. `WP_ENVIRONMENT_TYPE` в `wp-config.php` → `production`. От этого зависит
   сразу многое: включатся счётчики аналитики, перестанет прятаться тестовая
   оплата, снова заработает отправка писем.
2. Отключить **«Тестовая оплата (staging)»** (штатный «Чек») и включить ЮKassa.
3. Убрать mu-plugin `whoopstore-staging-guard.php` — он держит весь сайт в
   `noindex, nofollow, noarchive` и глушит исходящие письма.
4. `blog_public` → 1. Пока он 0, `/wp-sitemap.xml` намеренно отдаёт 404.
5. Снять HTTP Basic Auth (настройка Caddy, не наша).
6. Отправитель писем: сейчас «Whoopstore staging» / `mast.promo@gmail.com` —
   заменить на почту магазина.
7. Название сайта: сейчас «Whoopstore staging».
8. Вписать номера счётчиков в «Настройки → Общие».
9. Удалить тестовые заказы (на 2026-09-16 их 27, с `#125`; все с пометкой
   «Тестовый заказ staging, не обрабатывать» либо в статусе `checkout-draft`)
   и служебные страницы «Пример страницы» и черновик «Refund and Returns
   Policy». Черновики `checkout-draft` WooCommerce создаёт сам на каждую
   попытку оформления и сам же удаляет — но только по расписанию, поэтому на
   стенде без cron они копятся.

## 3. Инфраструктура

* **WP-Cron не работает на стенде**: петлевой запрос WordPress к самому себе
  упирается в Basic Auth, в Action Scheduler накопилось 88 задач в очереди. На
  стенде это не мешает (уведомления уходят синхронно), но к запуску нужен
  рабочий cron, иначе не пойдут отложенные задачи WooCommerce. Решение —
  внешний cron на `wp-cron.php` и `DISABLE_WP_CRON`.
* **504 на участке Caddy → Beget** при параллельной загрузке статики. Наш
  сервер отдаёт 100 параллельных запросов за 77 мс; отказы возникают дальше по
  цепочке. Из-за этого браузерная проверка нестабильна. Чтобы измерить именно
  этот участок, нужны логин/пароль Basic Auth и доступ к логам Caddy.
* Резервные копии и точки отката: `.whoopstore-backups/` и `.pilot-baseline/`
  лежат вне репозитория, на диске стенда. **До приёмки пилота не удалять.**

## 4. При переносе на другой сервер

* Русский языковой пакет WooCommerce лежит в `wp-content/languages/` и **в git
  не попадает** — повторить `wp language plugin install woocommerce ru_RU`,
  иначе интерфейс вернётся к английскому.
* Секреты берутся только из `wp-config.php` (`WHOOPSTORE_TELEGRAM_*`) — их
  тоже нет в репозитории.
* Медиатека (`wp-content/uploads/`) в репозиторий не входит.
