# SEO-метаданные и аналитика (2026-09-16)

Закрывает требования ТЗ «сохранить SEO-метаданные, Метрику/GTM» и «URL/SEO/
аналитика сохранены» в той части, которую можно сделать без данных production
и без браузера.

## Что было

В `<head>` любой страницы стенда было только `<title>` ядра и `robots` от
Staging Guard. Не было ни `description`, ни Open Graph, ни canonical на
страницах, где его не ставит ядро. SEO-плагина в проекте нет.

WooCommerce при этом уже отдаёт на страницах товара и в архивах разметку
schema.org (`WC_Structured_Data`): `Product` с ценой, наличием и изображением
плюс `BreadcrumbList`. Это проверено рендером — дублировать её не нужно и
вредно.

## Почему свой модуль, а не SEO-плагин

| Вариант | За | Против |
|---|---|---|
| Yoast / Rank Math | готовые поля метатегов у каждой страницы, sitemap, редиректы | установка плагина по ТЗ только по согласованию; своя разметка schema.org конфликтует с той, что уже отдаёт WooCommerce; большой объём настроек, который придётся обслуживать |
| **Свой mu-plugin (выбран)** | закрывает ровно то, чего нет; ничего не дублирует; ~250 строк, читается целиком | нет ручного редактирования метатегов по каждой странице |
| Ничего не делать | — | требование ТЗ остаётся невыполненным |

Выбран свой модуль. Если заказчику понадобится править метатеги руками по
каждой странице — это отдельное решение, и тогда SEO-плагин обоснован.

Код: `wp-content/mu-plugins/whoopstore-site.php` (загрузчик) и
`whoopstore-site/seo.php`. Почему mu-plugin, а не тема: метаданные принадлежат
сайту, а не оформлению, и при доработке темы пропадать не должны.

## Что выводится

| Тег | Источник |
|---|---|
| `description` | краткое описание товара → описание товара; описание категории; текст страницы; подзаголовок сайта на Главной |
| `og:title` | `wp_get_document_title()` ядра |
| `og:description` | то же, что `description` |
| `og:image` | фото товара → изображение записи → фон первого экрана (Главная, «Подписки») |
| `og:type` | `product` / `article` / `website` |
| `og:url`, `og:site_name`, `og:locale` | из настроек сайта |
| `product:price:amount` / `:currency` | цена товара |
| `twitter:card` | `summary_large_image`, если есть изображение |
| `canonical` | Главная, архив магазина, архивы терминов (на одиночных записях его ставит ядро) |

**Ничего не выдумывается.** Если описание собрать не из чего или оно короче
50 символов — тег просто не выводится. Так сделано осознанно: у страниц
каталогов контент состоит из заголовка и динамических блоков, и «описание» из
него дублировало бы `title`.

Отсюда фактическое состояние: `description` сейчас есть только у товара 13 —
единственного, у которого заполнено описание. **Остальным нужны тексты от
заказчика** (краткие описания товаров, описания категорий, подзаголовок сайта).

Страницы поиска и 404 метатеги не получают — в выдаче они не нужны. `robots`
модуль не трогает: стендом заведует Staging Guard (весь сайт `noindex`), а
корзиной, оформлением и кабинетом — сам WooCommerce (`wc_page_no_robots`).

## Аналитика

`whoopstore-site/analytics.php` — точка подключения Яндекс.Метрики и Google Tag
Manager. Номера счётчиков вписываются в **Настройки → Общие**, поля «Яндекс.
Метрика» и «Google Tag Manager». Пока поля пустые, на страницах не появляется
ничего.

**Счётчики не работают нигде, кроме production**: проверка идёт по
`WP_ENVIRONMENT_TYPE` (на стенде — `staging`). Слать визиты со стенда в реальный
счётчик нельзя — испортится статистика заказчика. Для проверки есть фильтр
`whoopstore_analytics_enabled`.

Чего сознательно нет: отправки товарных («рекламных») событий — просмотр
товара, добавление в корзину, покупка. Их состав и названия целей зависят от
того, как счётчик настроен у заказчика сейчас; своя схема событий дала бы
данные, которые не сойдутся с текущей статистикой.

**Нужно от заказчика:** номер счётчика Метрики, идентификатор контейнера GTM,
список целей и вариант e-commerce (Метрика или dataLayer GTM).

## Русские названия штатных страниц WooCommerce

Страницы 5–8 назывались по-английски — это попадало в `<title>`, хлебные крошки
и админку. Названия заменены формулировками из русского языкового пакета
WooCommerce: «Магазин», «Корзина», «Оформление заказа», «Мой аккаунт».
**Слаги (`/shop/`, `/cart/`, `/checkout/`, `/my-account/`) не менялись** — адреса
прежние. Это изменение в базе, в git его нет.

## Проверено

* отпечатки Главной, «Ремешков 5.0», «Ремешков MG» и «Подписок» совпали с
  baseline пилота по всему, кроме `<head>`: состав и порядок прямых потомков
  `<main>`, счётчики карточек и разделов, все цены — без изменений;
* 12 ключевых адресов отдают страницы без замечаний PHP и без битых ассетов
  (`tools/qa/smoke.php`);
* модуль аналитики на стенде не выводит ничего; при принудительном включении
  фильтром отдаёт оба счётчика и запасной кадр GTM после `<body>`.
