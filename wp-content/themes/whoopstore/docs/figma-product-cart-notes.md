# Страница товара + состояния корзины — заметки реализации (2026-09-11)

Источник: `docs/figma-design/states-and-components.md` и сырые дампы
`docs/figma-design/raw/states/*.code.tsx.txt` (fileKey `fUlpHpWsnxx78nCZKPxkkj`).
Новых вызовов Figma MCP не делалось — всё взято из уже сохранённых дампов.

## Архитектурное решение (согласовано с заказчиком 2026-09-11)

1. **Страница товара — классические шаблоны WooCommerce, а не WC-блоки.**
   `templates/single-product.html` теперь содержит только header/footer и блок
   `woocommerce/legacy-template` (Classic Template). Разметка переопределена
   штатным способом — копиями шаблонов в `wp-content/themes/whoopstore/woocommerce/`.
   Причина: в макете у галереи есть кнопка-лупа поверх фото и точки-пилюли под
   фото — это ровно то, что даёт классическая галерея WooCommerce
   (photoswipe + flexslider), то есть макет рисовался с неё. Блочная
   `woocommerce/product-gallery` ни того, ни другого не отдаёт.
2. **Чекаут «Ваш заказ» — только вёрстка.** Форма ничего не отправляет, заказ не
   создаёт, оплату не проводит; способы доставки и их цены — статические
   значения из Figma. Штатный `/checkout/` не тронут. Подключение к WooCommerce
   (billing/shipping, СДЭК/ПВЗ/экспресс/самовывоз, YooMoney) — отдельная задача.

## Данные корзины

Всё — через **WooCommerce Store API** (`/wp-json/wc/store/v1/cart`), штатный REST
корзины. Своих AJAX-ручек и своей модели корзины нет. Nonce действия
`wc_store_api` прокидывается через `wp_localize_script`; Store API отдаёт свежий
nonce заголовком `Nonce` в каждом ответе — скрипт его подхватывает.

Проверено на живых данных: `id` элемента = id **вариации**, `variation` =
`[{attribute:"Размер", value:"S"}]`, суммы — целые в минорных единицах
(`2499000` при `currency_minor_unit: 2`). Формат «₽ 24 990,00» из макета
собирается из полей валюты того же ответа.

## Аккордеоны «Таблица размеров» / «Доставка»

Это контент магазина, поэтому он живёт в **мета-полях товара**
(`_whoopstore_size_guide`, `_whoopstore_delivery`) с полями ввода в штатной
панели «Данные товара» (`inc/woocommerce/product-accordions.php`).
Пустое поле = аккордеон не выводится. У pilot-товара (ID 13) поля заполнены
текстами из Figma.

## Общие компоненты, затронутые правкой

* `.carousel-arrow` — круглая стрелка 27×27 вынесена из
  `.straps-carousel--personalize` в общий класс (разметку Главной не трогали,
  старый селектор остался в тех же правилах).
* `.device-card__price` — кегль исправлен с 20px на **14px** (mobile 13px).
  Старое значение в макете не встречается; по сырым дампам цена карточки
  всегда 14px. **Правка глобальная** — Главную и оба каталога ремешков стоит
  пересмотреть глазами.
* `whoopstore_device_card()` — добавлен параметр `price_html` для готовой
  разметки цены от WooCommerce.
* `[hidden] { display: none !important }` — общее правило в `theme.css`:
  переключение кнопка↔степпер, видимость drawer'а и модалки сделаны атрибутом
  `hidden`, а у этих компонентов свой `display`, перебивающий служебное правило
  браузера.
* `.page-head__crumb-link` + `.page-head__crumbs--current-bright` — крошки
  товара переиспользуют компонент крошек подстраниц.

## Лента related — полная ширина и центрирование

Уточнение заказчика 2026-09-11: лента не должна упираться в контентную
колонку; стрелки должны держаться за края первой и последней карточки, а не
за края страницы; при малом числе карточек ряд центрируется по экрану.
В Figma нарисованы ровно три карточки (360×3 + 20×2 = 1120 — впритык по
контенту), то есть прокручивать там нечего.

`.related-carousel__stage` — сетка из трёх колонок
(`auto minmax(0, auto) auto` = стрелка / лента / стрелка) с
`justify-content: center`, выведенная на всю ширину экрана тем же приёмом
`left:50% + 100vw + margin-left:-50vw`, что у `.faq` и `.balance-banner`.
Средняя колонка сама равна сумме карточек, пока они помещаются (тогда весь
ряд центрируется), и сжимается до доступной ширины, когда их много (тогда
лента прокручивается). Стрелки садятся центром ровно на край ленты через
`margin` −13.5px — как в макете (стрелка 26…53 при первой карточке от 40).

Заголовок «Вам может понравиться» перенесён ВНУТРЬ `.related-carousel__stage`
(строка 1, колонка ленты, `justify-self: start`) — иначе при центрировании
ряда он остался бы висеть отдельно на контентной сетке. Так он едет вместе с
лентой и стоит ровно над первой карточкой, как в Figma.

На mobile вся эта раскладка снимается (`display:block`, без full-bleed):
по макету там заголовок → строка из двух стрелок слева → лента от левого края
контента с выходом за правый.

## Поле количества

Убрано не стилями, а переопределением шаблонов
`single-product/add-to-cart/variation-add-to-cart-button.php` и
`single-product/add-to-cart/simple.php` (вместо `woocommerce_quantity_input()` —
скрытый input с минимальным количеством). Прятать его CSS'ом значило бы
держаться на специфичности против
`.woocommerce div.product form.cart div.quantity{display:inline-block}` из
woocommerce-blocktheme.css, плюс скрытый стилями `<input type="number">`
остаётся доступен с клавиатуры. CSS-правило оставлено страховкой на случай,
если поле напечатает какой-то другой шаблон.

## Простые товары в корзине (исправлено 2026-09-14)

До исправления кнопка-степпер-тост работали только у вариативных товаров.
`cart.js` искал id товара в `input[name=product_id]`, а это поле есть лишь в
нашем переопределении кнопки вариации. Штатный `simple.php` держит id только в
`button[name=add-to-cart]`, поэтому у простого товара отправка формы не
перехватывалась: страница перезагружалась обычным POST, тост и степпер не
появлялись. Для бизнес-этапа это блокер — простыми будет большинство товаров
(комплекты «устройство + тариф + срок», продления, зарядки).

Что сделано:

1. `currentId()` в `assets/js/cart.js` читает id из `button[name=add-to-cart]`,
   если нет полей вариации и `product_id`.
2. `woocommerce/single-product/add-to-cart/simple.php` — переопределение по
   образцу вариативного: скрытое поле количества (с тем же фильтром
   `woocommerce_quantity_input_min`, что у оригинала), всё остальное
   дословно — проверки `is_purchasable`/наличия, вывод остатка, все хуки,
   кнопка `button[name=add-to-cart]`. `@version 7.0.1` — версия оригинала в
   WooCommerce 9.7.3.
3. **Запасной обычный POST.** Если Store API не ответил на добавление, форма
   отправляется штатно. `form.submit()` не передаёт имя и значение нажатой
   кнопки, а у простого товара id лежит именно в ней — без правки WooCommerce
   получил бы форму без `add-to-cart` и ничего бы не добавил. Поэтому перед
   отправкой id переносится в скрытое поле `add-to-cart` (у вариативной формы
   оно уже есть, там ничего не добавляется).
4. **Ошибки Store API при изменении корзины** (степпер, удаление, «Очистить
   корзину»; например, товар закончился или превышен лимит количества) больше
   не падают необработанным промисом в консоль: корзина перечитывается, и
   интерфейс возвращается к фактическому состоянию WooCommerce. Отдельного
   сообщения об ошибке нет — такого состояния в макете нет. Неудачная первая
   загрузка корзины тоже гасится молча: кнопка корзины в шапке остаётся
   скрытой, форма товара работает через запасной POST.

## Горизонтальная прокрутка в drawer'е (исправлено 2026-09-11)

У панели корзины/чекаута появлялась горизонтальная полоса прокрутки, ломавшая
и desktop, и mobile. Две наложившиеся причины:

1. **Настоящая.** Поля адреса лежат в `grid-template-columns: repeat(2, 1fr)`,
   а `1fr` — это `minmax(auto, 1fr)`: минимум колонки равен min-content её
   содержимого. У `<input>` min-content — браузерная ширина по умолчанию
   (`size=20`, ~150px при 13px шрифте) плюс 48px паддингов `.checkout-field`,
   то есть колонка физически не могла стать уже ~200px. Пара «Дом /
   Квартира-офис» (по макету 204.5px на desktop и 157px на mobile) в эти
   200px не укладывалась. `min-width: 0` на `.checkout-field` снимает
   автоминимум, дальше поле сжимается штатно.
   Тот же `min-width: 0` добавлен плиткам доставки и названиям товаров
   (плюс `overflow-wrap: anywhere` — в названиях есть непереносимые куски
   вроде «Chestnut/Cream»).
2. **Усугубляющая.** У `.cart-drawer` стоял только `overflow-y: auto`, а по
   спецификации если одна ось не `visible`, вторая сама становится `auto` —
   то есть панель получала горизонтальную полосу от любого переполнения.
   Теперь `overflow-x: hidden` задан явно, как страховка.

## Специфичность против CSS WooCommerce

Собственный CSS WooCommerce (`woocommerce.css`, `woocommerce-layout.css`,
`woocommerce-blocktheme.css`) строит правила как
`.woocommerce div.product div.images …` — 3–4 класса плюс теги. Любой более
короткий селектор темы проигрывает им **независимо от порядка подключения
файлов**. Поэтому правила галереи, колонки данных, формы и related-секции
намеренно записаны длинно (`.woocommerce .product-page div.product div.images …`).
Снятые чужие правила: float-раскладка 48/48, `margin-bottom:2em` у галереи,
`block-gap` у каждого элемента `.summary`, `margin-top:5em` у `.related.products`.

## Известные ограничения / открытые вопросы

1. **Визуальной сверки в браузере не было** — стенд закрыт HTTP Basic Auth
   (Caddy, `www-authenticate: Basic realm="restricted"`), установить headless-
   браузер на хостинге не удалось. Всё проверялось по отрендеренной разметке
   (WP бутстрапится из CLI) и по координатам Figma.
2. ~~Related-секция не проверена вживую~~ — 2026-09-11 по согласованию созданы
   четыре pilot-товара из макета: ID **104/105/106** («Ремешок на бицепс …
   Royal Blue / Ash Grey / Jet Black», 14 490 ₽, SKU `PILOT-BICEP-*`) и ID
   **118** («Кожаный люксовый ремешок … Whoop 5.0 LeatherLuxe Straight Band
   Black/Cream with Titanium», 19 990 ₽, SKU `PILOT-50-LEATHERLUXE-BLACK` —
   он же в мобильном макете, node 30:1254/30:1255). Все в категории
   «Ремешки». `posts_per_page` у related по умолчанию 4, поэтому в ленте
   ровно четыре карточки и ей есть куда прокручиваться.
3. **Хлебные крошки** оставлены штатными WooCommerce (решение заказчика
   2026-09-11): «Ремешки / полное название товара» вместо «Whoop MG /
   Chestnut/Cream with Titanium» из макета — это данные товара, а не вёрстка.
4. **Активная миниатюра галереи** оставлена в штатном поведении WooCommerce
   (неактивные `opacity: .5`). В статичном кадре Figma все три миниатюры
   одинаково яркие — состояние выбора там не смоделировано.
   Подтверждено заказчиком 2026-09-11: приглушение оставляем.
5. **Zoom по наведению** на большом фото включён вынужденно: WooCommerce создаёт
   кнопку-лупу из макета только при `wc-product-gallery-zoom`. Два его штатных
   ограничения (разобраны 2026-09-11 по вопросу заказчика, это не наш баг):
   * зум навешивается **только на первый слайд** —
     `ProductGallery.prototype.initZoom` в `assets/js/frontend/single-product.js`
     буквально вызывает `initZoomForTarget( this.$images.first() )`;
   * и только если оригинал фото **шире зоны галереи**
     (`image.data('large_image_width') > galleryWidth`, у нас 645px). Наши фото
     ремешков 560×560, поэтому на них зума нет вовсе; сработал он на
     лайфстайл-кадре 800×800. Чтобы зум работал, нужны исходники шире 645px.

   Белый фон, "вспыхивавший" при наведении, — это `.zoomImg{background-color:#fff}`
   из CSS WooCommerce (расчёт на непрозрачные фото) поверх наших прозрачных PNG.
   Переопределён на фон фотозоны.
6. **Цена доставки** в чекауте (`₽ 100,00`) и «1-2 дня» — заглушки из макета;
   на плитке «Экспресс доставка» там же написано «1 500 ₽». Реальных shipping
   methods в магазине нет.
7. **Номер заказа 48291** в модалке — текст из макета, заказ не создаётся.
8. **Кнопка-корзина на mobile** по макету висит над правым верхним углом фото
   товара (y=153), а не в строке шапки. Правило ограничено страницей товара —
   для других мобильных страниц такого кадра в Figma нет.
9. **Фото товаров — настоящие, но частично подставные** (уточнение заказчика
   2026-09-11: «выбери любой более-менее подходящий, для удобства»).
   Главное фото товара 13 — родное `straps-mg-leatherluxe-straight-chestnut-
   cream-titanium.png`. Второй и третий кадры галереи — стенды: в каталоге
   ровно одно фото на SKU, второго ракурса того же ремешка нет, поэтому взяты
   фото версии Whoop **5.0** того же цвета и лайфстайл-кадр из плитки
   категории LeatherLuxe. У related-товаров фото родные. Все семь файлов уже
   лежали в uploads и зарегистрированы в медиатеке через
   `wp media import --skip-copy` (ID 111…117), alt проставлены.
10. **Размер миниатюр галереи** поднят со 100 до 120px
   (`gallery_thumbnail_image_width`). Для уже загруженных фото выполнен
   `wp media regenerate --only-missing`; при заливке новых он не нужен.

## Отложенные TODO (зафиксировано 2026-09-14)

Найдено при исправлении простых товаров в корзине. Решение заказчика — пока не
исправлять, каждый пункт — отдельная задача.

1. **`@version` у `variation-add-to-cart-button.php`.** В шапке переопределения
   нет тега `@version`, поэтому «Статус системы» WooCommerce не может сравнить
   его с оригиналом (7.0.1 в WooCommerce 9.7.3). Там же не применяется фильтр
   `woocommerce_quantity_input_min` к скрытому полю количества (в `simple.php`
   применяется).
2. **Минимальное количество.** `addItem()` в `assets/js/cart.js` всегда
   отправляет количество 1 и не читает скрытое поле `quantity`. Имеет значение
   только для товаров с минимальным количеством больше 1.
3. **Сгруппированные товары (grouped).** Правило
   `.woocommerce .product-page div.product div.summary div.quantity{display:none}`
   в `woocommerce.css` спрячет поля количества в таблице сгруппированного
   товара. Сейчас таких товаров нет, модель production неизвестна.
4. **Невыбранная вариация.** При `variation_id = 0` `currentId()` возвращает id
   родительского товара → Store API ответит ошибкой → запасной POST →
   уведомление WooCommerce. На практике недостижимо: WooCommerce блокирует
   кнопку, а пилюли размера сразу выбирают первый вариант.
5. **Английские уведомления WooCommerce.** После запасного обычного POST
   штатное уведомление остаётся на английском: «… has been added to your cart.
   View cart» (браузерная QA 2026-09-14). Отдельно не исправлять — решается
   общей локализацией WooCommerce (языковой пакет ru_RU), вместе с
   `screen-reader-text` цены со скидкой («Original price was…») и
   gettext-фильтрами в `inc/woocommerce/template-hooks.php`.
