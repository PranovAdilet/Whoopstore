«Блог» и «Whoop 4.0» выводятся `<span>`, а не `<a href="#">`: ссылка в «#»

**Зелёная подсветка «Whoop 5.0» — не «текущая страница».** В Figma этот пункт
зелёный на всех четырёх макетах страниц, то есть это постоянный акцент.
Оставлено как в макете; если нужна подсветка активного раздела — это отдельная
правка.

## Якоря секций

`$anchor` у `whoopstore_catalog_section()`), не руками в HTML:

| id | Секция | Где |
|---|---|---|
| `devices` | сетка трекеров | Главная |
| `accessories` | «Аксессуары» | Главная |
| `advantages` | блок преимуществ | Главная |
| `contacts` | контактный блок | Главная, Подписки, оба каталога ремешков |
| `buy` | «Купить Whoop с подпиской» | Подписки |

## Архив категории `/product-category/remeshki/`

Штатный архив WooCommerce, в Figma его нет. Решение заказчика: **301 на
`/remeshki-whoop-5-0/`** — `inc/woocommerce/redirects.php`, карта соответствий
в `whoopstore_category_redirects()` (одна строка на категорию, есть фильтр).
Архив не отключали: на него ведёт крошка «Ремешки» со страницы товара и на нём
завязана внутренняя логика WooCommerce.

## Страница 404 и результаты поиска (2026-09-16)

До этого оба адреса отдавали шапку, пустое место и подвал: в теме не было ни
`404.html`, ни `search.html`, и оба запроса попадали на `index.html`, где
`post-title` и `post-content` для них ничего не печатают. Посетитель, попавший
на битую ссылку, видел пустую страницу.

В Figma этих экранов нет, поэтому **своих текстов не добавлено** — взяты
формулировки из русских языковых пакетов:

| Где | Текст | Откуда |
|---|---|---|
| 404, H1 | «Страница не найдена» | WordPress |
| 404, кнопка на Главную | «Главная» | WordPress |
| Поиск, H1 | «Поиск» | WordPress |
| Поиск, заголовок выдачи | «Результат поиска: “…”» | WooCommerce |
| Поиск, пустая выдача | «Товаров, соответствующих вашему запросу, не обнаружено.» | WooCommerce |

Вёрстка тоже не новая: обе страницы используют `.page-head` и (у поиска)
`.catalog-section` с карточками `.device-card` — те же компоненты, что на
каталогах. **Новых правил CSS не потребовалось.**

Поиск ищет только по товарам (`whoopstore/search-results`,
`inc/blocks/search-results/`): в магазине поиск — это поиск товара, а главный
запрос WordPress смешал бы товары со страницами и сетка карточек развалилась
бы. Поля поиска в интерфейсе нет — его нет и в макете; адрес `/?s=…` остаётся
рабочим для внешних ссылок и закладок.

Проверено: `/?s=SuperKnit` — 20 карточек, `/?s=zzzqqq` — строка «ничего не
найдено», 404 отдаёт заголовок и кнопку. Отпечатки Главной, обоих каталогов и
«Подписок» не изменились.
