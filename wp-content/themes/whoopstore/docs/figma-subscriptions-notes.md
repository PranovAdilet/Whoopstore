### Единый источник данных для карточек с годовой подпиской

Секция 4 и первый ряд сетки на Главной — в Figma буквально одни и те же
карточки (совпадают названия, обе цены, бейдж «Распродажа»). Список вынесен в
`inc/product-data.php` → `whoopstore_annual_plan_devices()`; `device-grid.php`
теперь склеивает его со своими тремя «на 1 месяц». Иначе два списка с
одинаковыми ценами разъехались бы при первой же правке.

### Новые переиспользуемые части

- `.device-card--plan` — модификатор карточки товара под тариф: та же
  карточка (заголовок/цена/кнопка), другая медиа-зона (мокап телефона,
  фото браслета, слово-подложка `ONE`/`PEAK`/`LIFE`, растворение низа).
  `whoopstore_device_card()` получил необязательные `modifier`, `phone`,
  `watermark`.
- `whoopstore_page_head()` получил `inline` (акцент в той же строке, а не с
  новой) и `class` (для `.page-head--in-hero`).
- `.screen-reader-text` — в теме такого класса не было, добавлен под
  `<caption>` таблицы.

### Вертикальный ритм (координаты Figma)

- фотозона hero — 1200×665 от y=0, карточка 560×517 @ (40, 80);
- низ фотозоны 665 → заголовок «Выберите подписку» 737 = **72px**;
- карточки тарифов 789…1286 → верх выступающего мокапа 1426 = **140px**
  (сама светлая карточка при этом начинается на 1463, отсюда
  `calc(section-gap + 37px)`);
- низ светлой карточки 1839 → шапка таблицы 1979 = **140px**;
- низ таблицы ≈2764 → «Купить Whoop с подпиской» 2917 ≈ **140px**;
- низ карточек 3446 → help-block 3586 = **140px**.

### Геометрия таблицы

Колонки в макете отцентрованы по x = 373.5 / 599.5 / ~824 / 1052 при
контентной ширине 1120 — это ровно сетка «колонка подписей 220px + 4 равные
по 225px», поэтому таблица собрана на `table-layout: fixed`, а не на
подогнанных вручную процентах.

## Открытые вопросы

1. **Опечатка в макете.** Последняя строка таблицы — «Ежедневные показатели
   **эпотребительного** давления». Такого слова нет, по смыслу — вероятно
   «артериального». Выведено ДОСЛОВНО как в Figma (копию не выдумываю).
   Нужно решение: править контент или макет.
2. **Mobile-раскладка таблицы отличается от макета осознанно.** В Figma на
   mobile сравнение перестроено в горизонтально прокручиваемые карточки-колонки
   по планам (187×850, node 1:3996), где подписи критериев повторяются внутри
   каждой карточки. Из той же разметки это не собрать — пришлось бы
   продублировать все подписи в DOM ×4, то есть завести второй источник тех же
   данных ради мобильной раскладки. Сейчас на mobile таблица прокручивается по
   горизонтали с залипающей колонкой подписей: данные те же, разметка одна.
   Если нужно ровно как в макете — скажи, сделаю отдельным проходом.
3. **Битые ассеты Figma** (пустой PNG): фото браслета в карточках тарифов
   (`XxHSGND0LxCtAUYxCMxR 2`) и фото трекера в колонке ONE таблицы. Взяты
   одноимённые реальные ассеты, которые пользователь ранее вручную перезалил
   для Главной (`XxHSGND0LxCtAUYxCMxR-1/-2.png`) — пропорции совпадают.
   Для PEAK / LIFE / ПРОБНАЯ ассеты из Figma **побайтово совпали** (md5) с уже
   лежащими `device-whoop-peak-annual.png` / `device-whoop-life-annual.png` —
   новых копий не заводили.
4. Кнопки «Купить» / «Подключить» / «Написать нам» ведут на `#` — целевых URL
   нет, товаров WooCommerce тоже.
