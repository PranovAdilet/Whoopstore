# Аудит «Главная»: Figma vs текущая реализация (стейдж whoop.1c2.ru)

Дата: 2026-09-07
Источники:
- Figma-спека: `figma-design/homepage-desktop.md`, `figma-design/homepage-mobile.md`, `figma-design/README.md` (данные из `get_design_context`, подтверждены — где не подтверждено, помечено ⚠️ в самой Figma-споке).
- Текущая реализация: живой HTML/CSS со стейджа `https://whoop.1c2.ru/` (basic auth), файл темы `wp-content/themes/whoopstore/assets/css/theme.css?ver=0.1.0-pilot`, плюс два предоставленных скриншота полной страницы (desktop 1200×13155, mobile 360×17251).
- Код не менялся, это только аудит.

Общий вывод по структуре: **порядок и состав секций сверху вниз совпадает с Figma 1:1** (header → hero → device-grid → accessories → activation → straps-compact-promo → help-block → advantages → analytics-banner → straps-personalize(main) → app-promo → audience → balance-banner → no-display → faq → contacts → telegram-subscribe → footer). Расхождения — не в структуре страницы, а внутри секций: стили, контент, интерактивность.

## Список расхождений

### CRITICAL

---
Секция: FAQ ("Частые вопросы")
Элемент: `.faq__item` / `.faq__question`
Figma: Каждый пункт — отдельная тёмная **карточка** `bg-[#1b1e23] rounded-[10px]`, паттерн "компактная тёмная карточка" (см. README, повторяющиеся компоненты п.5), 550×80 (desktop) / 320×80 (mobile), иконка плюс/шеврон 16×16 справа.
Текущая реализация: `.faq__list { border-top: 1px solid rgba(255,255,255,.1) }`, `.faq__item { border-bottom: 1px solid rgba(255,255,255,.1) }` — плоский список без фона и без border-radius, разделённый линиями (аккордеон-таблица, а не стопка карточек).
Различие: Полностью другой визуальный паттерн — нет фона `#1b1e23`, нет `border-radius: 10px`, нет отступов карточки между пунктами.
Что необходимо изменить: Обернуть каждый `.faq__item` в карточку `background: var(--wp--preset--color--surface); border-radius: 10px;` с внутренними отступами, убрать общий `border-top/border-bottom`, добавить `gap` между карточками (аналогично `.card`, но с 10px радиусом вместо 20px — нужен модификатор `.card--compact` или отдельный radius-токен).
Приоритет: Critical

---
Секция: Отсутствие дисплея → "Отсутствие дисплея дает несколько преимуществ" (no-display__benefits)
Элемент: `.no-display__benefits`
Figma: **4 разных пункта** (desktop подтверждено `get_design_context`): "Длительная автономность" (активный, белый текст) / "Компактность" (приглушён) / "Датчики работают постоянно" (приглушён) / "Никаких отвлекающих факторов" (приглушён), разделены вертикальными линиями, похоже на carousel/tabs с одним активным пунктом.
Текущая реализация: В DOM присутствует **только 1 карточка** — "Длительная автономность" / "До 14 дней автономной работы без подзарядки". Остальные 3 пункта отсутствуют полностью. CSS (`grid-template-columns: repeat(auto-fit, minmax(220px,1fr))`) рассчитан на несколько карточек, но контента нет.
Различие: 3 из 4 пунктов отсутствуют в разметке; нет активного/приглушённого состояния, нет разделительных линий.
Что необходимо изменить: Добавить оставшиеся 3 пункта (тексты для "Компактность"/"Датчики работают постоянно"/"Никаких отвлекающих факторов" нужно запросить у Figma — README отмечает, что тексты этих трёх пунктов ещё не вытащены построчно, только заголовки-категории подтверждены; сверить перед вёрсткой), реализовать активное/приглушённое состояние (`rgba(255,255,255,0.2)` для неактивных, по дизайн-системе) и разделители между пунктами.
Приоритет: Critical

Секция: Analytics banner ("WHOOP непрерывно анализирует…")
Элемент: `.analytics-banner`
Figma: ✅ Подтверждено — **светлая карточка** (`bg-white rounded-[20px]`), редкий кейс на всей теме тёмной странице. Заголовок и текст — тёмные (`#0f1217` / `rgba(15,18,23,0.9)`).
Текущая реализация: `background: var(--wp--preset--color--surface)` = `#1b1e23` (тёмная), текст наследует `foreground`/`foreground-muted` (белый/полупрозрачный белый) — секция выглядит как обычная тёмная карточка, никак не выделяется на фоне остальной страницы.
Различие: Цвет фона карточки и текста инвертирован относительно Figma (тёмная вместо светлой, светлый текст вместо тёмного).
Что необходимо изменить: Добавить light-card модификатор (`background: #fff; color: #0f1217;`), пересчитать вторичный текст под `rgba(15,18,23,.9)`, кнопку `.wp-block-button.is-style-outline` внутри секции — уже подтверждённый как Primary `bg-[#02f1a0]` с тёмным текстом `#0f1217` (сейчас это outline-кнопка с `rgba(255,255,255,.16)` — тоже неверно, см. отдельный пункт ниже).
Приоритет: Critical

Секция: Контакты (contact-block)
Элемент: `.contact-block__info`

Секция: Персонализируйте свой WHOOP / straps-carousel (главный, не compact)
Элемент: `.straps-carousel__media`
Figma: ✅ Подтверждено — карусель из **7 фото ремешков** 246×369 каждое, шаг 186px, внахлёст без gap (`1:432`, Group 1000010470, -81,7038,1362,369).
Текущая реализация: `.straps-carousel__media` — **один статичный квадратный плейсхолдер** 220×220 (`repeating-linear-gradient`), без карусели, без нескольких изображений вообще.
Различие: Вместо горизонтальной ленты из 7 внахлёст расположенных фото ремешков — единственный маленький статичный блок-заглушка. Это не "недостающая картинка", а отсутствующий целиком компонент карусели.
Что необходимо изменить: Реализовать горизонтальную ленту из 7 карточек-фото 246×369 с шагом 186px (desktop) / 166px (mobile, по Figma-мобильной споке), см. `raw/homepage-desktop.supplementary-sections.code.tsx.txt` блок 9 для точных offset-значений.
Приоритет: Critical

---
Секция: Глобально / Responsive-типографика
Элемент: Все заголовки с классами `has-hero-font-size` / `has-xl-font-size` / `has-lg-font-size` / `has-md-font-size` и т.д.
Figma: Mobile H1 = `Onest:Regular/SemiBold 26px`, `tracking-[-0.26px]` (подтверждено в `homepage-mobile.md`) — заметно меньше desktop.
Текущая реализация: В `theme.css` единственный breakpoint `@media (max-width: 781px)` **не переопределяет ни один font-size** — переменные `--wp--preset--font-size--hero/xl/lg/md` остаются теми же (46/35/22/20px) что и на desktop. Значит H1 на мобильном рендерится 46px вместо ожидаемых Figma 26px, и аналогично все H2/H3 секций остаются desktop-размера.
Различие: Нет мобильного масштабирования типографики вообще — фиксированные px на всех брейкпоинтах.
Что необходимо изменить: Добавить в `@media (max-width: 781px)` переопределение custom properties (`--wp--preset--font-size--hero: 26px; --xl: ...; --lg: ...; --md: ...` и т.д. — точные mobile-значения выписать по каждой секции из `homepage-mobile.md`/`raw/homepage-mobile.code.tsx.txt`).
Приоритет: Critical (глобальная проблема, затрагивает вообще все секции и, вероятно, остальные страницы сайта — требует отдельной проверки `page-50`, `page-mg`, `page-subscriptions`).

Секция: Footer
Элемент: `.site-footer__nav-item` — первый пункт "Whoop 5.0"
Figma: Активный пункт в футере (как и в хедере) — `text-[#02f1a0]` `Onest:Medium`, остальные — `white Regular`.

Секция: Advantages / ECG (sticky-scroll)

Секция: Global / Onest:Light
Элемент: `@font-face` для Onest
Figma: Использует начертание `Onest:Light` для юридического мелкого текста (футер-карточка контактов, копирайт).
Текущая реализация: Подключены только `@font-face Onest` c `font-weight: 400 700` (два файла, latin/cyrillic) — начертание Light (300) не покрыто диапазоном шрифта, эти тексты рендерятся обычным Regular (400), т.к. отдельного файла/начертания для 300 нет.
Различие: Юридический текст в контактах не получает "лёгкое" начертание, как в Figma.
Что необходимо изменить: Добавить `@font-face` для Onest Light (weight 300) либо расширить variable-font диапазон, если файл это поддерживает.
Приоритет: Medium

## Повторяющиеся проблемы (можно чинить одним общим CSS/паттерном)

1. **"Светлая карточка на тёмном фоне" отсутствует как компонент.** И `analytics-banner`, и `contact-block__info` по Figma должны быть белыми, но оба используют общий `.card`/`--surface` (тёмный). Нужен один переиспользуемый класс/модификатор `.card--light` (`background:#fff; color:#0f1217;` + пересчитанные приглушённые оттенки текста), который закроет сразу 2 Critical-пункта.
2. **Плейсхолдеры вместо реальных фото** — `repeating-linear-gradient` diagonal-stripe паттерн используется в: `device-card__media` (все товарные карточки), `straps-carousel__media` (оба варианта), `analytics-banner__media`, `no-display__media`, `contact-block__map`, `telegram-subscribe__media`. Это самая заметная на глаз причина "выглядит незавершённым" на скриншотах — почти вся страница состоит из полосатых заглушек вместо фото. Не по одному пункту на каждую секцию, а системная нехватка контента/ассетов (изображения из Figma истекают через ~7 дней согласно README — нужно перезалить как ассеты темы).
3. **Отсутствие мобильного масштабирования типографики** — единая причина, почему на mobile практически все заголовки будут визуально "слишком крупными" относительно Figma (см. Critical, Global).
4. **Неполные списки при подтверждённом Figma-контенте большем, чем в разметке** — паттерн повторяется трижды: no-display__benefits (1 из 4), audience marquee (6 из 8 на desktop), help-block icons (1 из 3). Похоже на общий процесс "секция сверстана, но контент не долит до конца" — стоит пройтись по всем секциям главной и сверить количество карточек/пунктов с Figma построчно, не только эти три.

## Изменения, затрагивающие глобальные стили (проверить на других страницах)

- Отсутствие mobile font-size overrides — общий `theme.css`, применяется на всех страницах (5.0, MG, Подписки), не только на Главной.
- Отсутствующий `.card--light` компонент — если появится, вероятно, понадобится и на других страницах (там тоже могут быть light-card секции по тому же паттерну дизайн-системы).
- `@font-face Onest Light` — общесайтовый шрифтовой файл, повлияет на все страницы с мелким/юридическим текстом.
- `is-style-outline`-кнопка (единый стиль на тёмном фоне) — если её логику менять для light-card контекста, нужно завести отдельный модификатор, не трогая её использование в остальных (тёмных) секциях по всему сайту.
